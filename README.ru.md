Бесплатная программа с открытым кодом для терминала macOS. Она проводит звукового волонтёра церкви через
замер зала и настройку системы на **Behringer X32 / Midas M32**: кроссовер между сабвуфером и основными
колонками, согласование саба, системный эквалайзер, проверку и отчёт.

В небольших церквях звуком обычно занимаются волонтёры без подготовки, а профессиональная настройка системы
стоит $1000–3000. ChurchTune стремится сделать эту работу за одну репетицию: читает с пульта всё, что может,
говорит, куда поставить микрофон, измеряет, предлагает изменения, безопасно записывает их с файлом отмены,
измеряет ещё раз и говорит, стало ли лучше.

> [!WARNING]
> **Pre-alpha. Пока не используйте на рабочей системе.** Все шаги мастера есть и работают на эмуляторе пульта
> с имитацией зала, но на настоящем пульте ещё ничего не пробовали. Сначала проверки на оборудовании и пилот
> в настоящих церквях (M7). См. [Состояние проекта](#состояние-проекта).

## Установка

Откройте на Mac программу «Терминал» и вставьте одну строку:

```bash
curl -LsSf https://raw.githubusercontent.com/mihailShumilov/ChurchAutoTune/main/scripts/install.sh | sh
```

[Скрипт](scripts/install.sh) ставит [uv](https://docs.astral.sh/uv/), если его ещё нет, и затем команду `ctune`
с собственным Python. Пароль администратора не нужен. В конце он запускает самопроверку. После этого откройте
новое окно Терминала.

Если uv у вас уже есть, то же самое делает одна команда:

```bash
uv tool install "churchtune @ https://github.com/mihailShumilov/ChurchAutoTune/archive/main.tar.gz"
```

Чтобы обновить, выполните ту же строку ещё раз. Чтобы удалить: `uv tool uninstall churchtune` (ваши замеры
в `~/ChurchTune` останутся).

## Первые шаги

```bash
ctune selftest           # проверить установку: весь мастер на встроенном эмуляторе, без звука
ctune --emulator         # попробовать мастер на встроенном эмуляторе пульта с имитацией зала
ctune --help             # все команды
```

`ctune selftest` и `ctune --emulator` работают только со встроенным в программу эмулятором пульта и имитацией
зала: к настоящему пульту они не обращаются и звук не воспроизводят.

С настоящим пультом мастер запускается просто командой `ctune`. Пока пилот не пройден, делайте это только в
рамках [проверок на оборудовании](docs/hardware-checklist.md) и сначала сохраните сцену на пульте.

## Как это работает

Пошаговый мастер (на английском, русском или украинском) ведёт по шагам:

1. **Чтение пульта.** Модель, прошивка, маршрутизация, какая матрица или шина питает основные колонки и саб,
   текущий эквалайзер и маршрутизация USB для замера.
2. **Замер.** Один или несколько измерительных микрофонов (например, Behringer ECM8000) на входах пульта.
   Несколько микрофонов сначала калибруются между собой. Свипы играют через USB-карту пульта, в нескольких
   местах зала, и каждый свип проверяется на качество.
3. **Анализ.** Средняя по местам АЧХ, разброс между местами, реверберация (RT60) и стык сабвуфера с основными
   колонками.
4. **Предложения.** Пакеты изменений на выбор: кроссовер, уровень саба, широкие полосы системного эквалайзера в
   строгих пределах и советы по задержке и полярности. Программа прямо говорит и о том, чего эквалайзер не
   исправит (акустика зала).
5. **Применение.** Таблица всех изменений, подтверждение вводом слова, файл отмены до первого изменения и
   обратное чтение каждого записанного значения с пульта.
6. **Проверка и отчёт.** Повторный замер, сравнение, предложение всё вернуть. В конце пишется отчёт: страница,
   которая открывается без интернета, Markdown, JSON и короткий текст для чата.

Метод взят из рабочего инструмента, которым 2026-10-02 настроили один настоящий зал. Эта сессия входит в
эталонные (golden) тесты.

## Состояние проекта

ChurchTune делается по этапам (см. [SPEC §15](docs/SPEC.md)).

| Этап | Что входит | Состояние |
|---|---|---|
| M0 | Репозиторий, проверенный инструмент перенесён в пакет со слоями, эталонные тесты | готово |
| M1 | Драйвер X32/M32: поиск пульта, полное чтение без записи, схема колонок | готово |
| M2 | Аудио и замер: один или несколько микрофонов, калибровка, проверка сигнала | готово |
| M3 | Пошаговый мастер, сохранение прогресса, английский / русский / украинский | готово |
| M4 | Анализ и предложения | готово |
| M5 | Применение, отмена, проверочный замер, кроссовер | готово, на настоящем пульте ещё не пробовали |
| M6 | Отчёт | готово |
| M7 | Проверки на оборудовании и пилот в настоящих церквях, установка одной командой, выпуск 0.1.0 | в работе |

Выпусков пока нет. Версия 0.1.0 выйдет, когда полный мастер пройдёт на настоящем X32 Producer с результатом не
хуже ручной сессии 2026-10-02, а все пункты чек-листа оборудования проверит человек.

## Безопасность

Звуковая система может повредить слух и колонки, а пульт в церкви должен работать в воскресенье. Поэтому:

- **По умолчанию только чтение.** Клиент пульта читает лишь из фиксированного списка адресов. Пишет один
  модуль, и только с разрешением политики безопасности на один вид изменений.
- **Пределы.** Подъём и вырез эквалайзера, добротность, кроссовер и изменения уровня ограничены. Всё, что за
  пределами, отклоняется, а не обрезается.
- **Сначала отмена.** Файл отмены лежит на диске до первой записи и никогда не перезаписывается.
- **Обратное чтение.** Каждая запись читается с пульта обратно и сверяется.
- **Тихий звук.** С компьютера не выходит ничего громче −6 dBFS по пику. Плавное нарастание и затухание при
  каждом старте и остановке. Ctrl+C сразу останавливает звук.
- **Непроверенные настройки не пишутся.** Задержка выходов и полярность матриц на настоящем пульте ещё не
  проверены. Мастер даёт их значения для ручной установки; экспертная командная строка пишет их только с
  `--write-unverified` ([ADR 0005](docs/adr/0005-unverified-writes-opt-in.md)).
- **Разработка не трогает оборудование.** С `CTUNE_DEV_SAFE=1` код отказывается от любого пульта не на
  `127.0.0.1` и от любого аудиоустройства, кроме имитации. Все тесты идут так.

Поведение оборудования подтверждает только человек у пульта, это записывается в
[`docs/hardware-checklist.md`](docs/hardware-checklist.md).

## Что нужно

- Mac (целевая платформа macOS; на Linux в CI идут тесты).
- Для настоящей работы: Behringer X32 / Midas M32 (прошивка 4.x) с картой X-USB, подключённый к Mac по сети и
  USB, и измерительный микрофон.
- Python 3.12 и всё остальное ставит установщик.

## Разработчикам

```bash
git clone https://github.com/mihailShumilov/ChurchAutoTune.git
cd ChurchAutoTune
uv sync
CTUNE_DEV_SAFE=1 uv run pytest -q                 # все тесты: эмулятор X32 + имитация аудио
CTUNE_DEV_SAFE=1 uv run ctune --emulator          # мастер на эмуляторе
CTUNE_DEV_SAFE=1 uv run ctune --emulator doctor   # найти, прочитать и объяснить эмулированный X32
```

Полная проверка, как в CI:

```bash
CTUNE_DEV_SAFE=1 uv run ruff format --check . && uv run ruff check . && uv run mypy \
  && CTUNE_DEV_SAFE=1 uv run pytest --cov --cov-report=json && uv run python scripts/check_coverage.py
```

Экспертные команды помимо мастера — переходные и пока выводят тексты по-русски
([ADR 0003](docs/adr/0003-transitional-expert-cli.md)).
