**Сайт:** <https://mihailshumilov.github.io/ChurchAutoTune/> (English, Українська, Español): стан проєкту, план
та інструкція.

Безкоштовна програма з відкритим кодом для терміналу macOS. Вона проводить звукового волонтера церкви через
замір залу й налаштування системи на **Behringer X32 / Midas M32**: кросовер між сабвуфером і основними
колонками, узгодження саба, системний еквалайзер, перевірку та звіт.

У невеликих церквах звуком зазвичай займаються волонтери без підготовки, а професійне налаштування системи
коштує $1000–3000. ChurchTune прагне зробити цю роботу за одну репетицію: читає з пульта все, що може, каже,
куди поставити мікрофон, вимірює, пропонує зміни, безпечно записує їх із файлом скасування, вимірює ще раз і
каже, чи стало краще.

> [!WARNING]
> **Pre-alpha. Поки не використовуйте на робочій системі.** Усі кроки майстра є й працюють на емуляторі пульта
> з імітацією залу, але на справжньому пульті ще нічого не пробували. Спершу перевірки на обладнанні й пілот у
> справжніх церквах (M7). Див. [Стан проєкту](#стан-проєкту).

## Встановлення

Відкрийте на Mac програму «Термінал», вставте цей рядок і натисніть Return:

```bash
curl -LsSf https://raw.githubusercontent.com/mihailShumilov/ChurchAutoTune/main/scripts/install.sh | sh
```

[Скрипт](scripts/install.sh) встановлює [uv](https://docs.astral.sh/uv/), якщо його ще немає, а потім команду
`ctune` з власним Python і додає її в PATH. Пароль адміністратора не потрібен. Наприкінці він запускає
самоперевірку: якщо в останніх рядках «Самоперевірку пройдено», усе гаразд. Потім відкрийте нове вікно Терміналу,
щоб команда `ctune` знайшлася.

Якщо uv у вас уже є, можна встановити напряму (самоперевірка тоді сама не запуститься):

```bash
uv tool install --reinstall --force "churchtune @ https://github.com/mihailShumilov/ChurchAutoTune/archive/main.tar.gz"
```

Щоб оновити, виконайте рядок встановлення ще раз. Щоб видалити: `uv tool uninstall churchtune` (ваші заміри в
`~/ChurchTune` залишаться).

## Перші кроки

```bash
ctune selftest --lang uk # перевірити встановлення: увесь майстер на вбудованому емуляторі, без звуку
ctune --emulator         # спробувати майстер на вбудованому емуляторі пульта з імітацією залу
ctune --help             # усі команди
```

`ctune selftest` і `ctune --emulator` працюють лише з вбудованим у програму емулятором пульта та імітацією залу:
до справжнього пульта вони не звертаються й звук не відтворюють.

Щоб запустити майстер на справжньому пульті, наберіть просто `ctune`. Доки програму не випробували в справжніх
церквах, робіть це лише в межах [перевірок на обладнанні](docs/hardware-checklist.md) і спершу збережіть сцену на пульті.

## Як це працює

Покроковий майстер (англійською, російською чи українською) веде крок за кроком:

1. **Читання пульта.** Модель, прошивка, маршрутизація, яка матриця чи шина живить основні колонки й саб,
   поточний еквалайзер і маршрутизація USB для заміру.
2. **Замір.** Один або кілька вимірювальних мікрофонів (наприклад, Behringer ECM8000) на входах пульта. Кілька
   мікрофонів спершу калібруються між собою. Свипи грають через USB-карту пульта, у кількох місцях залу, і
   кожен свип перевіряється на якість.
3. **Аналіз.** Середня по місцях АЧХ, розкид між місцями, реверберація (RT60) і стик сабвуфера з основними
   колонками.
4. **Пропозиції.** Пакети змін на вибір: кросовер, рівень саба, широкі смуги системного еквалайзера в суворих
   межах і поради щодо затримки й полярності. Програма прямо каже й про те, чого еквалайзер не виправить
   (акустика залу).
5. **Застосування.** Таблиця всіх змін, підтвердження введенням слова, файл скасування до першої зміни й
   зворотне читання кожного записаного значення з пульта.
6. **Перевірка і звіт.** Повторний замір, порівняння, пропозиція все повернути. Наприкінці пишеться звіт:
   сторінка, що відкривається без інтернету, Markdown, JSON і короткий текст для чату.

Метод узято з робочого інструмента, яким 2026-10-02 налаштували один справжній зал. Ця сесія входить до
еталонних (golden) тестів.

## Стан проєкту

ChurchTune робиться поетапно (див. [SPEC §15](docs/SPEC.md)).

| Етап | Що входить | Стан |
|---|---|---|
| M0 | Репозиторій, перевірений інструмент перенесено в пакет із шарами, еталонні тести | готово |
| M1 | Драйвер X32/M32: пошук пульта, повне читання без запису, схема колонок | готово |
| M2 | Аудіо й замір: один або кілька мікрофонів, калібрування, перевірка сигналу | готово |
| M3 | Покроковий майстер, збереження прогресу, англійська / російська / українська | готово |
| M4 | Аналіз і пропозиції | готово |
| M5 | Застосування, скасування, контрольний замір, кросовер | готово, на справжньому пульті ще не пробували |
| M6 | Звіт | готово |
| M7 | Перевірки на обладнанні й пілот у справжніх церквах, встановлення однією командою, випуск 0.1.0 | у роботі |

Випусків поки немає. Версія 0.1.0 вийде, коли повний майстер пройде на справжньому X32 Producer із результатом
не гіршим за ручну сесію 2026-10-02, а всі пункти чек-листа обладнання перевірить людина.

## Безпека

Звукова система може пошкодити слух і колонки, а пульт у церкві має працювати в неділю. Тому:

- **Типово лише читання.** Клієнт пульта читає лише з фіксованого списку адрес. Пише один модуль, і лише з
  дозволом політики безпеки на один вид змін.
- **Межі.** Підйом і виріз еквалайзера, добротність, кросовер і зміни рівня обмежено. Усе, що поза межами,
  відхиляє фінальна перевірка (планувальник сабвуфера заздалегідь тримає свою ціль у межах).
- **Спершу скасування.** Файл скасування лежить на диску до першого запису й ніколи не перезаписується.
- **Зворотне читання.** Кожен запис читається з пульта назад і звіряється.
- **Тихий звук.** З комп'ютера не виходить нічого гучніше за −6 dBFS за піком. Плавне наростання й згасання на
  кожному старті й зупинці. Ctrl+C одразу зупиняє звук.
- **Неперевірені налаштування не записуються.** Затримку виходів і полярність матриць на справжньому пульті ще
  не перевірено. Майстер дає їхні значення для ручного встановлення; експертний командний рядок записує їх лише
  з `--write-unverified` ([ADR 0005](docs/adr/0005-unverified-writes-opt-in.md)).
- **Розробка не чіпає обладнання.** З `CTUNE_DEV_SAFE=1` код відмовляється від будь-якого пульта не на
  цьому комп'ютері (loopback, емулятор) і від будь-якого аудіопристрою, крім імітації. Усі тести йдуть так.

Поведінку обладнання підтверджує лише людина біля пульта, це записується в
[`docs/hardware-checklist.md`](docs/hardware-checklist.md).

## Що потрібно

- Mac (цільова платформа macOS; на Linux у CI йдуть тести).
- Для справжньої роботи: Behringer X32 / Midas M32 (прошивка 4.x) з картою X-USB, підключений до Mac мережею та
  USB, і вимірювальний мікрофон.
- Python 3.12 і все інше встановлює інсталятор.

## Розробникам

```bash
git clone https://github.com/mihailShumilov/ChurchAutoTune.git
cd ChurchAutoTune
uv sync
CTUNE_DEV_SAFE=1 uv run pytest -q                 # усі тести: емулятор X32 + імітація аудіо
CTUNE_DEV_SAFE=1 uv run ctune --emulator          # майстер на емуляторі
CTUNE_DEV_SAFE=1 uv run ctune --emulator doctor   # знайти, прочитати й пояснити емульований X32
```

Повна перевірка, як у CI:

```bash
CTUNE_DEV_SAFE=1 uv run ruff format --check . && uv run ruff check . && uv run mypy \
  && CTUNE_DEV_SAFE=1 uv run pytest --cov --cov-report=json && uv run python scripts/check_coverage.py
```

Експертні команди, крім майстра, перехідні й поки виводять тексти російською
([ADR 0003](docs/adr/0003-transitional-expert-cli.md)).
