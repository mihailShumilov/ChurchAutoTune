Qué puedes hacer hoy Ahora

  • Desarrolladores y testers pueden instalar el proyecto, correr las pruebas y probar la línea de comandos experta con el emulador de consola incluido y audio simulado. No se usa ninguna consola ni altavoz real.
  • Dueños de consolas pueden hacer una verificación en una X32 o M32 real y reportar el resultado. Es la ayuda más valiosa ahora mismo.
  • Si eres voluntario y quieres ajustar el sistema de tu iglesia, te pedimos que esperes al asistente guiado. Sigue los lanzamientos en GitHub para enterarte cuando esté listo.

El equipo que necesitarás

Para el ajuste real, más adelante. Nada de esto hace falta para probar la versión para desarrolladores.

  • Una Mac (la aplicación está hecha para macOS).
  • Una Behringer X32 o Midas M32 con firmware 4.x y una tarjeta de audio USB: X-USB o X-LIVE en la X32, DN32-USB o DN32-LIVE en la M32. Las señales de prueba se reproducen y graban por esta tarjeta.
  • Un cable USB de la Mac a la consola y una conexión de red con la consola (cable o Wi-Fi), que ChurchTune usa para leer su configuración.
  • Un micrófono de medición, por ejemplo un Behringer ECM8000, con pedestal y cable XLR a una entrada de la consola. También está previsto usar varios micrófonos a la vez, con calibración.
  • Un salón vacío y silencioso y unas 1–2 horas.

Para desarrolladores y testers

Todo lo siguiente funciona solo con un emulador en tu propia computadora y audio simulado. Pon siempre CTUNE_DEV_SAFE=1 delante de los comandos que ejecutan la aplicación o las pruebas: así el código rechaza cualquier consola real y cualquier dispositivo de audio real.

1. Instalar

Necesitas macOS o Linux, Python 3.12 y uv (uv puede instalar Python por ti). En Debian o Ubuntu instala también libportaudio2 libsndfile1.

git clone https://github.com/mihailShumilov/ChurchAutoTune.git
cd ChurchAutoTune
uv sync

2. Correr las pruebas

CTUNE_DEV_SAFE=1 uv run pytest -q                # todas: emulador de consola + audio simulado
CTUNE_DEV_SAFE=1 uv run pytest tests/golden -q   # la sesión real del salón, 2026-10-02

3. Probar la línea de comandos con el emulador

Por ahora el emulador de consola vive dentro de las pruebas (un comando ctune emulator está previsto para M1). Inícialo en una terminal; mostrará su puerto:

CTUNE_DEV_SAFE=1 uv run python -c "import time; from tests.emulator.x32_emulator import X32Emulator; e = X32Emulator().start(); print('Emulator port:', e.port, flush=True); time.sleep(3600)"

En una segunda terminal, ejecuta la revisión de solo lectura con audio simulado (cambia PORT):

CTUNE_DEV_SAFE=1 uv run ctune --console 127.0.0.1:PORT --audio fake --home /tmp/ctune-demo check
CTUNE_DEV_SAFE=1 uv run ctune --help

Por ahora los textos de la línea de comandos están en ruso. Es una herramienta provisional para desarrolladores; en M3 la reemplaza el asistente para voluntarios.

4. Antes de un pull request

CTUNE_DEV_SAFE=1 uv run ruff format --check . && uv run ruff check . && uv run mypy \
  && CTUNE_DEV_SAFE=1 uv run pytest --cov --cov-report=json && uv run python scripts/check_coverage.py

Lee primero la guía para colaborar (en inglés), sobre todo las reglas de seguridad.

Para dueños de consolas: verificaciones de equipo

Parte del comportamiento de la consola solo lo puede confirmar una persona frente a una consola real. Cada verificación es una fila de la lista de verificación de equipos (en inglés). Tu reporte hace que una función pase de «solo consejo» a «ChurchTune puede escribir esto» para ese modelo y firmware.

Antes de empezar

  • Hazlo con el salón vacío, nunca durante un culto o un ensayo.
  • Mantén el sistema a un nivel bajo y seguro.
  • Guarda una escena en la consola primero, para poder restaurarlo todo.
  • Instala la versión para desarrolladores en la Mac (ver Instalar arriba) y conéctala a la red de la consola.

Pasos

  1. Abre la lista de verificación y elige una fila para tu consola. Las filas 1 y 2 (ctune hwcheck delay y ctune hwcheck polarity) ya se pueden hacer hoy; las demás dependen de funciones que aún se están construyendo.
  2. Lee la fila: qué verificar, el comando y el resultado esperado.
  3. Ejecuta el comando mirando la pantalla de la consola. Compara lo que pasa con el resultado esperado.
  4. Restaura el valor anterior como indica la fila (con el archivo para deshacer o recuperando tu escena).
  5. Envía el resultado con el formulario de verificación de equipo: el número de fila, el modelo y firmware de tu consola, el commit de ChurchTune (git rev-parse --short HEAD) y lo que viste. El formulario está en inglés; basta con frases sencillas.

Volcados de consola

Los volcados de solo lectura de otros modelos, versiones de firmware y ruteos ayudan al controlador de la consola (M1) a reconocer más sistemas. Quita antes los nombres y cualquier dato personal; la guía para colaborar explica cómo.

Más adelante: ajustar tu sistema Más adelante

Así está previsto que funcione el asistente guiado cuando terminen las etapas M3–M6. Todavía no existe.

  1. Leer la consola. ChurchTune encuentra la consola y muestra lo que encontró, por ejemplo: «X32 Producer, altavoces principales en Matrix 1/2, subwoofer en Matrix 3. ¿Es correcto?». Solo pregunta lo que no puede leer.
  2. Medir. Encuentra la entrada del micrófono, comprueba el camino de la señal con un tono corto y suave, ajusta el nivel y luego muestra un mapa sencillo de puntos y te guía: «pon el micrófono aquí y pulsa Enter».
  3. Analizar. Promedia los puntos y revisa el salón, incluido cuánto resuena y cómo se une el subwoofer con los altavoces principales.
  4. Proponer. Muestra los problemas con palabras sencillas y sugiere unos pocos cambios, cada uno con un breve «por qué».
  5. Aplicar. Ves cada cambio y lo confirmas escribiendo; primero se guarda un archivo para deshacer y cada valor se relee después de escribirlo.
  6. Verificar e informar. Mide de nuevo, muestra el antes y el después, ofrece deshacer si no mejoró, guarda un informe y te recuerda guardar una escena en la consola.
