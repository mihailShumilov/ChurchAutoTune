Guía

ChurchTune hoy

Una guía honesta de lo que puedes hacer ahora y de lo que viene. Crecerá con cada etapa.

Última actualización: 14 de octubre de 2026

Pre-alfa. El asistente guiado lee la consola, mide, propone cambios y puede escribirlos, con deshacer y una medición de comprobación. La escritura en una consola real todavía no se ha verificado en equipo real: todo se ha probado solo con el emulador y un salón simulado. Solo funciona desde el código fuente. No lo uses todavía en el sistema en uso de tu iglesia. Mira la hoja de ruta.

Qué puedes hacer hoy Ahora

  • Cualquiera que se maneje con una terminal puede recorrer el asistente guiado con el emulador de consola incluido y un salón simulado: sin consola, sin altavoces, sin sonido. Mira Probar el asistente sin equipo.
  • Desarrolladores y testers pueden instalar el proyecto, correr las pruebas y probar la línea de comandos experta con el emulador.
  • Dueños de consolas pueden hacer una verificación en una X32 o M32 real y reportar el resultado. Es la ayuda más valiosa ahora mismo.
  • Los desarrolladores pueden recorrer el asistente hasta el final con el emulador: la medición separada del subwoofer y los altavoces principales, la aplicación de los cambios y la medición de comprobación (mira Qué verás en la demostración). También pueden aplicar un plan de cambios y deshacerlo desde la terminal (mira Aplicar y deshacer desde la terminal).
  • Si eres voluntario y quieres ajustar el sistema de tu iglesia, te pedimos que esperes. El asistente ya puede escribir los cambios, pero eso solo se ha probado con el emulador, nunca en una consola real (la etapa M5 está en curso). Sigue los lanzamientos en GitHub para enterarte cuando esté listo.

El equipo que necesitarás

Para el ajuste real, más adelante. Nada de esto hace falta para probar la versión para desarrolladores.

  • Una Mac (la aplicación está hecha para macOS).
  • Una Behringer X32 o Midas M32 con firmware 4.x y una tarjeta de audio USB: X-USB o X-LIVE en la X32, DN32-USB o DN32-LIVE en la M32. Las señales de prueba se reproducen y graban por esta tarjeta.
  • Un cable USB de la Mac a la consola y una conexión de red con la consola (cable o Wi-Fi), que ChurchTune usa para leer su configuración.
  • Un micrófono de medición, por ejemplo un Behringer ECM8000, con pedestal y cable XLR a una entrada de la consola. ChurchTune también puede usar varios micrófonos a la vez y calibrarlos entre sí; por ahora esto solo se ha probado con micrófonos simulados.
  • Un salón vacío y silencioso y unas 1–2 horas.

Para desarrolladores y testers

Todo lo siguiente funciona solo con un emulador en tu propia computadora y audio simulado. Pon siempre CTUNE_DEV_SAFE=1 delante de los comandos que ejecutan la aplicación o las pruebas: así el código rechaza cualquier consola real y cualquier dispositivo de audio real.

1. Instalar

Necesitas macOS o Linux, Python 3.12 y uv (uv puede instalar Python por ti). En Debian o Ubuntu instala también libportaudio2 libsndfile1.

git clone https://github.com/mihailShumilov/ChurchAutoTune.git
cd ChurchAutoTune
uv sync

2. Correr las pruebas

CTUNE_DEV_SAFE=1 uv run pytest -q                # todas: emulador de consola + audio simulado
CTUNE_DEV_SAFE=1 uv run pytest tests/golden -q   # la sesión real del salón, 2026-10-02

3. Probar la línea de comandos con el emulador

Mientras los pull requests #8–#11 y el trabajo de M5 no estén fusionados, los comandos de abajo están solo en sus ramas; la más nueva es m5b-mutes. En tu copia:

git checkout m5b-mutes
uv sync

Lo más rápido es la opción global --emulator: arranca un emulador de consola dentro del programa durante ese comando.

CTUNE_DEV_SAFE=1 uv run ctune --emulator doctor     # revisar la computadora y la consola, explicar el esquema de altavoces
CTUNE_DEV_SAFE=1 uv run ctune --help                # todos los comandos

También puedes iniciar el emulador aparte en una terminal (muestra su puerto y funciona hasta Ctrl+C) y usarlo desde una segunda terminal, cambiando PORT:

CTUNE_DEV_SAFE=1 uv run ctune emulator --model X32P
CTUNE_DEV_SAFE=1 uv run ctune --console 127.0.0.1:PORT --audio fake --home /tmp/ctune-demo doctor

La salida de la mayoría de los comandos expertos sigue en ruso; el asistente de abajo está traducido. La línea de comandos experta se queda como herramienta para desarrolladores junto al asistente.

4. Antes de un pull request

CTUNE_DEV_SAFE=1 uv run ruff format --check . && uv run ruff check . && uv run mypy \
  && CTUNE_DEV_SAFE=1 uv run pytest --cov --cov-report=json && uv run python scripts/check_coverage.py

Lee primero la guía para colaborar (en inglés), sobre todo las reglas de seguridad.

Probar el asistente sin equipo Ahora

El asistente guiado es lo que usarán los voluntarios. Ya hoy puedes recorrerlo con el emulador de consola incluido y un salón simulado. Nada sale de tu computadora: no se toca ninguna consola y no suena nada.

La escritura en una consola real todavía no está verificada en equipo real. Los pasos que escriben en la consola solo se han probado con el emulador y un salón simulado. No los uses en la consola de tu iglesia hasta que alguien haya hecho las verificaciones de equipo en un salón real (filas 22–28 de la lista de verificación).

Iniciarlo

Desde una copia del repositorio con uv instalado, en la rama m5b-mutes (mira Instalar y el paso 3):

uv sync
CTUNE_DEV_SAFE=1 uv run ctune --emulator --audio fake --home /tmp/ctune-demo                                  # asistente a pantalla completa
CTUNE_DEV_SAFE=1 uv run ctune --emulator --audio fake --home /tmp/ctune-demo wizard --plain --lang uk         # interfaz de líneas, en ucraniano
CTUNE_DEV_SAFE=1 uv run ctune --emulator --audio fake --home /tmp/ctune-demo resume                           # continuar la sesión guardada

--emulator usa el emulador de consola incluido, --audio fake el salón simulado, y --home guarda los archivos de la demostración aparte de los reales (sin esta opción van a ~/ChurchTune). --lang acepta en, ru o uk; el español todavía no está disponible en la aplicación. La interfaz de líneas (--plain) funciona con lectores de pantalla y en scripts.

Teclas

  • Ctrl+C o la barra espaciadora: detener el sonido al instante, en cualquier pantalla.
  • Esc: volver un paso atrás, donde la pantalla lo permite.
  • Ctrl+Q: guardar y salir. Para seguir más tarde: ctune resume.
  • En la interfaz de líneas: Enter elige la respuesta recomendada, B vuelve atrás, Q guarda y sale, y Ctrl+C detiene el sonido, guarda y sale.

Qué hace el asistente hoy

16 pasos, o 15 con un solo micrófono. Los pasos «Subwoofer y altavoces principales por separado», «Aplicar los cambios» y «Medición de comprobación» aparecen solo cuando eliges cambiar el sistema (ajuste completo o solo el subwoofer); el primero de ellos, solo cuando el sistema tiene subwoofer. El progreso se guarda después de cada paso.

  1. Inicio: el nombre del salón y qué quieres hacer hoy.
  2. Revisión de la Mac: la computadora y la tarjeta de audio USB de la consola.
  3. Consola: encuentra la consola en la red, te pide confirmarla y comprueba la conexión.
  4. Lectura de la consola: lee toda su configuración sin cambiar nada y te pide guardar una escena en la consola.
  5. Altavoces: muestra qué salida alimenta los altavoces principales, el subwoofer, los monitores, etc., y te pide confirmar las salidas de las que no está seguro.
  6. Equipo: unas preguntas que la consola no puede responder: altavoces activos o pasivos, tamaño de la zona de público (ancho × fondo en metros, para el plan de puntos; si lo dejas vacío se usa un plan estándar), cuántos micrófonos de medición y de qué modelo.
  7. Micrófonos: rascas cada micrófono y el asistente encuentra su entrada. Te dice qué hacer en la consola, por ejemplo encender +48V o poner mute a ese canal.
  8. Camino de reproducción: comprueba que el sonido de la computadora va a los altavoces del salón y no a los monitores ni a la transmisión.
  9. Nivel: ajusta un nivel de medición seguro.
  10. Calibración de micrófonos: solo con varios micrófonos; los compara entre sí.
  11. Medición: un plan de lugares en el salón y luego barridos de prueba en cada lugar (mira más abajo).
  12. Subwoofer y altavoces principales por separado: en algunos lugares mide solo el subwoofer, solo los altavoces principales y todo junto, con mute breves después de teclear una palabra (mira más abajo).
  13. Resultados y propuestas: lo que se midió, con palabras sencillas, y luego los paquetes de cambios y los consejos sobre los canales de entrada (mira más abajo).
  14. Aplicar los cambios: escribe los paquetes que elegiste, después de leer la consola de nuevo y de que escribas una palabra (mira más abajo).
  15. Medición de comprobación: vuelve a medir algunos asientos y dice si mejoró (mira más abajo).
  16. Qué sigue: qué hacer después de esta sesión, por ejemplo guardar la escena en la consola con un nombre nuevo.

El plan de puntos de medición

Antes de las rondas de medición, el asistente prepara un plan de lugares donde se sienta la gente:

  • Al menos 8 asientos en la parte central del salón, fuera del pasillo central y a distancias irregulares entre sí.
  • Cada lugar se describe con palabras y distancias, por ejemplo «filas delanteras, izquierda, a unos 6 m del escenario, 3,5 m a la izquierda del pasillo central». Izquierda y derecha, mirando hacia el escenario.
  • Un mapa sencillo del salón muestra el escenario arriba y numera solo los lugares de la ronda actual.
  • El micrófono va a la altura de los oídos de una persona sentada (1,2 m), apuntando al escenario. Después de Enter tienes 3 segundos para alejarte al menos 2 m.
  • Si no diste el tamaño del salón, el plan es para un salón típico de 12 × 18 m y colocas los micrófonos de forma aproximada.
  • El plan se guarda para ese lugar, para que una medición de comprobación posterior use los mismos puntos.

El subwoofer y los altavoces principales por separado

Para saber dónde se encuentra el subwoofer con los altavoces principales, y si ahí se cancelan entre sí, el asistente los mide por separado en los puntos de unión del plan. En cada lugar reproduce tres barridos seguidos: solo el subwoofer, solo los altavoces principales y luego todo junto.

  • Para eso el programa pone mute en la consola al subwoofer o a los altavoces principales durante unos segundos. Solo pone mute a sus matrices (las salidas que alimentan los altavoces), nunca a Main LR ni a un canal de entrada.
  • Antes pregunta. Para permitir los mute breves tecleas la palabra que pide el asistente en tu idioma: en la interfaz inglesa mute (en la rusa заглушить, en la ucraniana заглушити) y pulsas Enter. Una línea vacía salta esta medición; entonces no se propone ningún crossover.
  • Antes del primer mute lee la consola y guarda cómo estaba cada interruptor. Justo después de los tres barridos devuelve todos los interruptores, también si detienes el sonido con Ctrl+C o la barra espaciadora.
  • Si una medición se interrumpió antes de que volvieran los interruptores (por ejemplo, la computadora perdió la conexión), la próxima vez el asistente los devuelve primero: vuelve a leer la consola, muestra lo que va a encender de nuevo y pide la misma palabra. Si la consola no lo confirma, te dice qué matrices encender a mano.
  • Esto solo funciona cuando el subwoofer y los altavoces principales salen cada uno de su propia matriz. Si no, el asistente lo dice, salta esta medición y no propone un crossover.

Paquetes de cambios y consejos sobre los canales

Después de los resultados, el asistente propone cambios en paquetes. Cada paquete tiene su propia pantalla:

  • una tabla con lo que cambia: dónde, el valor actual y el valor propuesto;
  • por qué ayuda el cambio, el efecto esperado y el riesgo;
  • la pregunta «¿Añadir … al plan de cambios?», con «Añadir al plan» o «Dejarlo fuera».

Si dejas fuera un paquete, los siguientes se calculan de nuevo sin él, así que nada en el plan depende de un cambio que no elegiste. Tus elecciones se guardan en la carpeta de la sesión, en el archivo proposal.json.

Con el subwoofer y los altavoces principales medidos por separado, el asistente puede proponer hasta cuatro paquetes, en este orden:

  • el crossover: los graves van solo al subwoofer y el resto solo a los altavoces principales;
  • la alineación del subwoofer: un pequeño retardo y quizá un cambio de polaridad, para que lleguen juntos. Este es solo un consejo: lo pones a mano en la consola;
  • el nivel del subwoofer, para que los dos suenen más o menos igual de fuerte donde se encuentran;
  • la ecualización del sistema: correcciones suaves de lo que el salón le hace al sonido en la mayoría de los asientos. Las muescas estrechas en asientos sueltos no se tocan, porque la ecualización no puede corregirlas.

Sin esa medición (la saltaste, o los altavoces no salen de su propia matriz) el asistente propone solo la ecualización del sistema y explica por qué: un crossover puesto a ciegas puede dejar un hueco en los graves.

Después vienen los consejos sobre los canales de entrada. El programa nunca los cambia por sí mismo; tú decides de oído, un ajuste a la vez, en un ensayo:

  • voces sin corte de graves (filtro pasa altos, HPF) o con uno muy alto;
  • cortes estrechos que probablemente protegen contra el acople: hacerlos como mucho la mitad de profundos, en un ensayo, con los monitores encendidos;
  • cortes compartidos por muchos canales;
  • cortes muy profundos: revisar si todavía hacen falta, de 3 dB en 3 dB;
  • realces grandes, que pueden causar acople;
  • alimentación fantasma (+48V) en lo que parece un micrófono dinámico: apágala solo con el canal en mute.

En este paso no se escribe nada en la consola. La escritura llega en el paso siguiente, «Aplicar los cambios».

Aplicar los cambios

Después de las propuestas, el paso Aplicar los cambios escribe los paquetes que elegiste:

  • Primero vuelve a leer la consola. Si alguien cambió un ajuste desde la medición, rechaza el plan y te pide medir de nuevo, para que el plan siempre corresponda a lo que la consola tiene ahora.
  • Muestra cada ajuste que va a escribir, con el valor actual y el nuevo, en el orden en que los escribirá.
  • Para escribir, teclea la palabra apply (en la interfaz rusa применить, en la ucraniana застосувати) y pulsa Enter. Cualquier otra cosa cancela y no se escribe nada.
  • Los valores anteriores se guardan en un archivo para deshacer antes de la primera escritura.
  • El orden de las escrituras está elegido para que el sonido nunca suba de volumen a mitad de camino. Cuando un crossover no se puede alcanzar así, el programa pone mute un momento a la matriz del subwoofer o de los altavoces principales mientras la cambia: oyes un corte breve del subwoofer o de los altavoces principales, nunca un salto de volumen.
  • Si el nuevo nivel del subwoofer queda a más de 12 dB del que tenía cuando el programa leyó este salón por primera vez, antes hace una pregunta aparte (la respuesta segura es «no»).
  • Cada valor se vuelve a leer de la consola. Si alguno no se confirma, el asistente se detiene ahí y ofrece devolver lo que ya se escribió.
  • El programa no escribe el retardo de salida ni la polaridad. Justo después de las escrituras los muestra como valores para que los pongas a mano en la consola, antes de la medición de comprobación.

La medición de comprobación

Luego el paso Medición de comprobación vuelve a medir al menos cuatro asientos, entre ellos el que peor sonaba y el del centro del salón. Pon los micrófonos exactamente donde estaban antes. Con reglas fijas dice una de tres cosas: mejor, sin diferencia notable o peor, con un pequeño dibujo de antes y después. Si empeoró, recomienda devolver los valores anteriores y ofrece hacerlo en ese mismo momento.

La última pantalla te recuerda guardar la escena en la consola con un nombre nuevo (por ejemplo con la fecha de hoy), para que los ajustes nuevos sigan ahí después de reiniciar. También muestra el comando para devolver los valores anteriores más tarde.

Aplicar y deshacer desde la terminal

La línea de comandos experta hace lo mismo: ctune apply-packages escribe los paquetes elegidos de un proposal.json guardado, y ctune undo devuelve los valores anteriores. Úsalos solo con el emulador y CTUNE_DEV_SAFE=1. Necesitan un proposal.json de una sesión del asistente (en la carpeta de la sesión, <home>/venues/<salón>/sessions/<hora>-<objetivo>/). La forma más fácil de obtener uno es recorrer la demostración con el emulador hasta las propuestas (mira más abajo).

Primero mira sin escribir nada. --dry-run muestra los ajustes que escribiría, en orden, y se detiene:

CTUNE_DEV_SAFE=1 uv run ctune --emulator apply-packages SESSION/proposal.json --dry-run

--emulator arranca un emulador nuevo solo para ese comando. Para escribir y luego deshacer, deja un emulador funcionando en su propia terminal (muestra su puerto) y apunta los dos comandos a él, cambiando PORT, SESSION y UNDO_FILE:

CTUNE_DEV_SAFE=1 uv run ctune emulator --model X32P
CTUNE_DEV_SAFE=1 uv run ctune --console 127.0.0.1:PORT --audio fake --home /tmp/ctune-demo apply-packages SESSION/proposal.json
CTUNE_DEV_SAFE=1 uv run ctune --console 127.0.0.1:PORT --audio fake --home /tmp/ctune-demo undo UNDO_FILE

apply-packages guarda el archivo para deshacer antes de la primera escritura y muestra su nombre (está en la carpeta undo dentro de --home). undo devuelve solo los valores que nadie cambió a mano desde entonces, y lista los que deja como están. Los dos comandos aceptan también --dry-run. Sus textos todavía están en ruso, así que piden las palabras rusas применить (aplicar) y вернуть (devolver). Para scripts, apply-packages --yes-i-am-at-the-console confirma sin la palabra tecleada; todo lo demás sigue igual (la lectura nueva, el archivo para deshacer, la relectura).

Seguridad antes de cualquier sonido

  • El asistente nunca pone ni quita un mute a un canal de entrada. En una consola real tú pones mute a mano a los canales de los micrófonos de medición, y el asistente te dice cuáles. Lo único a lo que pone mute por su cuenta son las matrices de los altavoces, unos segundos, después de una palabra tecleada (mira más arriba), y durante una escritura cuando no hay otro orden seguro.
  • Antes del primer sonido vuelve a leer la consola. Mientras un canal que escucha un micrófono de medición no tenga mute y pueda llegar a los altavoces, se niega a reproducir cualquier sonido, porque podría causar acople.
  • Esta comprobación ve los canales. Un micrófono ruteado directamente a una salida, sin pasar por un canal, todavía no se comprueba, así que revisa tú el ruteo.
  • Cada sonido tiene primero una pantalla de aviso («Reproducir el sonido de prueba» o «Todavía no»), y las rondas de medición cuentan 3 segundos hacia atrás.

Qué verás en la demostración

La demostración recorre todo el asistente. Nadie puede pulsar los botones del emulador, así que al empezar la demostración pone mute ella misma a los canales de sus micrófonos de medición, como lo haría una persona en una consola real. El salón simulado escucha al emulador: el sonido de prueba pasa por la ecualización de Main LR, y cada altavoz suena solo mientras su matriz está encendida.

Así puedes seguir cada paso: el plan de puntos, la medición separada del subwoofer y los altavoces principales con sus mute breves, los paquetes de cambios (con el crossover), la aplicación, la medición de comprobación y la última pantalla. Elige al principio el ajuste completo (o solo el subwoofer) para llegar a los pasos que escriben. Guarda y sal cuando quieras con Ctrl+Q (Q en la interfaz de líneas). En una consola real el asistente no pone mute por ti a los canales de los micrófonos: ahí espera a que lo hagas tú.

Lo que todavía no hace

  • Nunca escribe el retardo de salida ni la polaridad: siguen siendo valores para poner a mano hasta que se verifiquen en una consola real.
  • La revisión de los altavoces uno por uno todavía no está en el asistente. Hoy existe solo como comando experto.
  • Todavía no hay archivo de informe (M6).
  • Todavía no se ha usado en una consola real, y la escritura en una consola real no está verificada en equipo real. Para eso hacen falta las verificaciones de equipo y la prueba piloto (M7).

Para dueños de consolas: verificaciones de equipo

Parte del comportamiento de la consola solo lo puede confirmar una persona frente a una consola real. Cada verificación es una fila de la lista de verificación de equipos (en inglés). Tu reporte hace que una función pase de «solo consejo» a «ChurchTune puede escribir esto» para ese modelo y firmware.

Antes de empezar

  • Hazlo con el salón vacío, nunca durante un culto o un ensayo.
  • Mantén el sistema a un nivel bajo y seguro.
  • Guarda una escena en la consola primero, para poder restaurarlo todo.
  • Instala la versión para desarrolladores en la Mac (ver Instalar arriba) y conéctala a la red de la consola.

Pasos

  1. Abre la lista de verificación y elige una fila para tu consola. Las filas 1 y 2 (ctune hwcheck delay y ctune hwcheck polarity) ya se pueden hacer hoy; las demás dependen de funciones que aún se están construyendo. Las filas 22–28 verifican la nueva escritura de M5 (aplicar, deshacer, la medición de comprobación, los mute breves de las matrices, la medición separada del subwoofer y los altavoces principales y el crossover); necesitan la rama m5b-mutes, y una persona tiene que hacerlas en un salón vacío antes de que alguien confíe en estas escrituras.
  2. Lee la fila: qué verificar, el comando y el resultado esperado.
  3. Ejecuta el comando mirando la pantalla de la consola. Compara lo que pasa con el resultado esperado.
  4. Restaura el valor anterior como indica la fila (con el archivo para deshacer o recuperando tu escena).
  5. Envía el resultado con el formulario de verificación de equipo: el número de fila, el modelo y firmware de tu consola, el commit de ChurchTune (git rev-parse --short HEAD) y lo que viste. El formulario está en inglés; basta con frases sencillas.

Volcados de consola

Los volcados de solo lectura de otros modelos, versiones de firmware y ruteos ayudan al controlador de la consola (M1) a reconocer más sistemas. Quita antes los nombres y cualquier dato personal; la guía para colaborar explica cómo.

Más adelante: ajustar tu sistema Más adelante

Así está previsto que funcione el asistente completo en un salón real cuando terminen las etapas M5 y M6. Leer la consola, medir, analizar, proponer, aplicar y la medición de comprobación ya están en el asistente (mira más arriba); el informe llega con M6.

La escritura en una consola real todavía no está verificada en equipo real. Aplicar, deshacer, los mute breves y la medición de comprobación solo se han probado con el emulador y un salón simulado. Espera a que terminen las verificaciones de equipo antes de usarlos en el sistema de tu iglesia.

  1. Leer la consola. ChurchTune encuentra la consola y muestra lo que encontró, por ejemplo: «X32 Producer, altavoces principales en Matrix 1/2, subwoofer en Matrix 3. ¿Es correcto?». Solo pregunta lo que no puede leer.
  2. Medir. Encuentra la entrada del micrófono, comprueba el camino de la señal con un tono corto y suave, ajusta el nivel y luego muestra un mapa sencillo de puntos y te guía: «pon el micrófono aquí y pulsa Enter».
  3. Analizar. Promedia los puntos y revisa el salón, incluido cuánto resuena y cómo se une el subwoofer con los altavoces principales.
  4. Proponer. Muestra los problemas con palabras sencillas y sugiere unos pocos cambios, cada uno con un breve «por qué».
  5. Aplicar. Ves cada cambio y lo confirmas escribiendo; primero se guarda un archivo para deshacer y cada valor se relee después de escribirlo.
  6. Verificar e informar. Mide de nuevo, muestra el antes y el después, ofrece deshacer si no mejoró, guarda un informe y te recuerda guardar una escena en la consola.
