Free · Open source · macOS · X32 / M32

Clear church sound, tuned step by step

ChurchTune is a free app for the Mac that will guide sound volunteers through measuring the room and tuning a Behringer X32 or Midas M32: where the subwoofer meets the main speakers, the subwoofer's level and timing, and the overall tone of the system. Plain words, strict limits, and every change can be undone.

Star on GitHub See the roadmap

In development (pre-alpha). ChurchTune is not ready for a live system yet. Star or watch the project to hear when it is, and see where it stands.

Why ChurchTune exists

In most small churches, sound is run by volunteers who never had training. The speaker system is often set up by ear, or not set up at all.

  • Volunteers, not engineers

    People learn the faders, mutes and scenes. Nobody explains crossovers or how a room changes sound. That is not their fault.

  • The same problems everywhere

    A hole where the subwoofer meets the main speakers, boomy voices, speech that is hard to understand, and deep EQ cuts on every vocal channel to fight what is really a system problem.

  • Professional tuning is expensive

    A professional system tune costs about $1,000–3,000. Many small churches cannot pay that, and it is hard to repeat when something changes.

ChurchTune aims to do this work in one rehearsal: about 60–90 minutes in an empty hall, with a volunteer who knows the console only at a basic level.

Built on a real tuning session

The method is not just theory. It comes from a working tool that tuned one real church hall on 2 October 2026. That session is now part of the project's automated tests, so the new app has to reproduce its results.

  • ~101 Hzcrossover between the subwoofer and the main speakers (Linkwitz-Riley, 24 dB/octave)
  • Sub levelsubwoofer level matched to the main speakers
  • ~480 Hz cutsystem EQ cut for a build-up in the low mids that made voices boomy
  • ~50 Hz cutsystem EQ cut for a room resonance (a room mode)

One hall is a start, not proof that it works everywhere. That is why tests in more churches matter.

How it will work

Six steps. The measurement and design core already works; the guided wizard that walks you through these steps is still being built. More in the guide.

  1. Read the console

    It reads the model, firmware, routing, which outputs feed the main speakers and the subwoofer, and the current EQ. It asks you only what it cannot read.

  2. Measure

    You put a measurement microphone (for example a Behringer ECM8000) where it tells you. It plays short test sweeps through the console's USB card at several spots in the room and checks every sweep.

  3. Analyse

    It averages the sound over all spots, sees how much the spots differ, measures how long the room rings (RT60) and looks closely at where the subwoofer meets the main speakers.

  4. Propose

    It suggests a crossover, subwoofer level, delay and polarity, and a few broad EQ corrections, all within strict limits. It also tells you what EQ cannot fix, such as the room's acoustics.

  5. Apply

    You see every change before it happens and confirm it by typing. An undo file is saved first, and each value is read back from the console to make sure it was written correctly.

  6. Verify and report

    It measures again, compares before and after, offers to undo if the sound did not get better, and writes a report you can keep.

Safety first

A sound system can hurt ears and speakers, and your church needs its console on Sunday. These rules are part of the design, not an afterthought.

  • Read-only by default

    The part that talks to the console can only read. One separate module writes, and only the settings the safety policy allows for that step.

  • Strict limits

    EQ cuts and boosts, crossover and level changes have fixed limits. A change outside them is refused, not quietly trimmed.

  • Undo file first

    An undo file is saved before the first change and is never overwritten, so you can always go back.

  • Every write is checked

    After each change, ChurchTune reads the value back from the console and compares it with what it meant to write.

  • Quiet test sounds

    Nothing louder than −6 dBFS peak leaves the computer. Sound fades in and out, and Ctrl+C stops it at once.

  • Hands off everything else

    It does not change routing, phantom power, gain, scenes, effects or channel EQ. For those it only gives advice.

  • Untested writes stay off

    Settings never checked on a real console yet (output delay and polarity) are written only if you allow it explicitly.

  • Development never touches hardware

    Developers and automated tests use a console emulator and simulated audio only. In that mode the code refuses real consoles and real audio devices.

Project status

Not ready for live use yet. The measurement and design core works and reproduces the real session, but the guided wizard does not exist yet, and some console writes were never checked on real hardware. Please do not use ChurchTune on your church's system yet.

Questions and answers

Which consoles does it work with?

It is being built for the Behringer X32 and Midas M32 family with firmware 4.x and a USB audio card (such as the X-USB card in an X32). So far the method has been used on one X32 Producer. Other models need hardware checks, which is why your reports matter. Other consoles, such as X Air, WING, Allen & Heath or Yamaha, are not part of the first version.

Do I need a measurement microphone?

Yes, for example a Behringer ECM8000, plugged into a console input. One microphone is enough: you move it from spot to spot. Using several microphones at once is planned too. A vocal microphone will not do, because it is not made to hear all frequencies evenly.

Is it only for macOS?

Yes, the app is made for a Mac connected to the console. The core is written so it could run elsewhere, and the automated tests also run on Linux, but Windows and Linux are not supported in the first version.

Is it free?

Yes. It is free and open source under the GPL-3.0-or-later license. No accounts, no subscriptions, no telemetry.

Will it break my console?

It is designed not to. It changes only a few system settings within strict limits, saves an undo file first and checks every value after writing it. It never touches routing, gain, phantom power or scenes. But it is pre-alpha: do not use it on a live system yet, and save a scene on the console before any test.

Can it fix bad room acoustics?

No. EQ can soften some problems, but it cannot remove echo or a long, muddy reverb. ChurchTune measures how long the room rings and tells you plainly what EQ cannot fix.

When will it be ready?

There is no date yet. The guided wizard is planned for milestone M3, and the first release (0.1.0) comes after a pilot in real churches. Follow the roadmap and watch releases on GitHub.
