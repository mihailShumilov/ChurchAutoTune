ChurchTune сьогодні

Чесна інструкція: що можна зробити вже зараз і що буде далі. Вона доповнюватиметься з кожним етапом.

Оновлено: 14 жовтня 2026

Pre-alpha. Покроковий майстер читає пульт, вимірює, пропонує зміни й уміє їх записувати, зі скасуванням і контрольним заміром. Запис у справжній пульт ще не перевірено на обладнанні: усе це перевірено лише на емуляторі з імітованим залом. Запускається лише з вихідного коду. Поки не використовуйте його на живій системі своєї церкви. Дивіться план.

Що можна зробити сьогодні Зараз

  • Кожен, хто вміє користуватися терміналом, може пройти покроковий майстер на вбудованому емуляторі пульта з імітованим залом: без пульта, без колонок, без звуку. Дивіться Спробувати майстер без обладнання.
  • Розробники й тестувальники можуть установити проєкт, запустити тести й спробувати експертний командний рядок на емуляторі.
  • Власники пультів можуть пройти перевірку на справжньому X32 чи M32 і повідомити результат. Зараз це найцінніша допомога.
  • Розробники можуть спробувати застосувати план змін і скасувати його з термінала на емуляторі (дивіться Застосування й скасування з термінала). В автоматичних тестах майстер проходить увесь шлях, разом із застосуванням і контрольним заміром, на емуляторі й імітованому залі.
  • Волонтерам, які хочуть налаштувати систему своєї церкви: будь ласка, зачекайте. Майстер уже вміє записувати зміни, але це перевірено лише на емуляторі, ніколи на справжньому пульті (етап M5 у роботі). Стежте за випусками на GitHub, щоб дізнатися, коли він буде готовий.

Яке обладнання знадобиться

Для справжнього налаштування — згодом. Для версії для розробників нічого з цього не потрібно.

  • Комп'ютер Mac (програма створюється для macOS).
  • Behringer X32 або Midas M32 з прошивкою 4.x і USB-аудіокартою: X-USB чи X-LIVE в X32, DN32-USB чи DN32-LIVE в M32. Через цю карту відтворюються й записуються тестові сигнали.
  • USB-кабель від Mac до пульта та мережеве підключення до пульта (кабель або Wi-Fi): через нього ChurchTune читає налаштування.
  • Вимірювальний мікрофон, наприклад Behringer ECM8000, зі стійкою та XLR-кабелем до входу пульта. ChurchTune може працювати й із кількома мікрофонами одночасно та калібрувати їх один відносно одного; поки це перевірено лише на імітованих мікрофонах.
  • Порожній тихий зал і приблизно 1–2 години.

Для розробників і тестувальників

Усе, що нижче, працює лише з емулятором на вашому комп'ютері та імітованим звуком. Завжди додавайте CTUNE_DEV_SAFE=1 перед командами, що запускають програму чи тести: тоді код відмовляється працювати з будь-яким справжнім пультом і аудіопристроєм.

1. Встановлення

Потрібні macOS або Linux, Python 3.12 і uv (uv може сам установити Python). На Debian чи Ubuntu також установіть libportaudio2 libsndfile1.

git clone https://github.com/mihailShumilov/ChurchAutoTune.git
cd ChurchAutoTune
uv sync

2. Запуск тестів

CTUNE_DEV_SAFE=1 uv run pytest -q                # усі тести: емулятор пульта + імітований звук
CTUNE_DEV_SAFE=1 uv run pytest tests/golden -q   # реальна сесія в залі 2026-10-02

3. Експертний командний рядок на емуляторі

Доки pull request #8–#11 і робота над M5 не злиті, наведені нижче команди є лише в їхніх гілках; найновіша — m5-apply. У вашій копії:

git checkout m5-apply
uv sync

Найпростіше — глобальний параметр --emulator: він запускає емулятор пульта всередині програми на час однієї команди.

CTUNE_DEV_SAFE=1 uv run ctune --emulator doctor     # перевірити комп'ютер і пульт, пояснити схему колонок
CTUNE_DEV_SAFE=1 uv run ctune --help                # усі команди

Можна також запустити емулятор окремо в одному терміналі (він виводить свій порт і працює до Ctrl+C) і звертатися до нього з другого терміналу, замінивши PORT:

CTUNE_DEV_SAFE=1 uv run ctune emulator --model X32P
CTUNE_DEV_SAFE=1 uv run ctune --console 127.0.0.1:PORT --audio fake --home /tmp/ctune-demo doctor

Вивід більшості експертних команд поки що російською; майстер нижче перекладено. Експертний командний рядок залишається інструментом для розробників поряд із майстром.

4. Перед pull request

CTUNE_DEV_SAFE=1 uv run ruff format --check . && uv run ruff check . && uv run mypy \
  && CTUNE_DEV_SAFE=1 uv run pytest --cov --cov-report=json && uv run python scripts/check_coverage.py

Спершу прочитайте посібник для учасників (англ.), особливо правила безпеки.

Спробувати майстер без обладнання Зараз

Покроковий майстер — це те, чим користуватимуться волонтери. Уже сьогодні його можна пройти на вбудованому емуляторі пульта з імітованим залом. Нічого не виходить за межі вашого комп'ютера: пульт не задіяний, звук не відтворюється.

Запис у справжній пульт ще не перевірено на обладнанні. Кроки, що записують у пульт, перевірені лише на емуляторі з імітованим залом. Не запускайте їх на пульті своєї церкви, доки люди не пройдуть перевірку обладнання в справжньому залі (рядки 22–25 чек-листа обладнання).

Запуск

З копії репозиторію з установленим uv, у гілці m5-apply (дивіться Встановлення і крок 3):

uv sync
CTUNE_DEV_SAFE=1 uv run ctune --emulator --audio fake --home /tmp/ctune-demo                                  # повноекранний майстер
CTUNE_DEV_SAFE=1 uv run ctune --emulator --audio fake --home /tmp/ctune-demo wizard --plain --lang uk         # рядковий інтерфейс українською
CTUNE_DEV_SAFE=1 uv run ctune --emulator --audio fake --home /tmp/ctune-demo resume                           # продовжити збережену сесію

--emulator вмикає вбудований емулятор пульта, --audio fake — імітований зал, а --home тримає файли демонстрації окремо від справжніх (без нього вони потрапляють у ~/ChurchTune). --lang приймає en, ru або uk. Рядковий інтерфейс (--plain) працює з програмами екранного доступу й у скриптах.

Клавіші

  • Ctrl+C або пробіл: негайно зупинити звук, на будь-якому екрані.
  • Esc: на крок назад, де екран це дозволяє.
  • Ctrl+Q: зберегти й вийти. Продовжити пізніше — ctune resume.
  • У рядковому інтерфейсі: Enter вибирає рекомендовану відповідь, B — назад, Q — зберегти й вийти, а Ctrl+C зупиняє звук, зберігає й виходить.

Що майстер робить сьогодні

15 кроків, або 14 з одним мікрофоном. Кроки «Застосувати зміни» й «Контрольний замір» з'являються лише тоді, коли ви вирішили змінювати систему (повне налаштування або лише сабвуфер). Прогрес зберігається після кожного кроку.

  1. Початок: назва зали й що ви хочете зробити сьогодні.
  2. Перевірка Mac: комп'ютер і USB-аудіокарта пульта.
  3. Пульт: знаходить пульт у мережі, просить підтвердити його й перевіряє з'єднання.
  4. Читання пульта: читає всі налаштування, нічого не змінюючи, і просить зберегти сцену на пульті.
  5. Колонки: показує, який вихід живить основні колонки, сабвуфер, монітори тощо, і просить підтвердити виходи, у яких він не впевнений.
  6. Обладнання: кілька питань, на які пульт не відповість: активні чи пасивні колонки, розмір зони слухачів (ширина × глибина в метрах, для плану точок; можна залишити порожнім, тоді буде стандартний план), скільки вимірювальних мікрофонів і якої моделі.
  7. Мікрофони: ви шкрябаєте кожен мікрофон, і майстер знаходить його вхід. Він підказує, що зробити на пульті, наприклад увімкнути +48V чи вимкнути (mute) цей канал.
  8. Шлях відтворення: перевіряє, що звук із комп'ютера йде в колонки залу, а не в монітори чи трансляцію.
  9. Рівень: підбирає безпечний рівень вимірювання.
  10. Калібрування мікрофонів: лише з кількома мікрофонами; порівнює їх між собою.
  11. Вимірювання: план місць у залі, потім тестові свіпи на кожному місці (дивіться нижче).
  12. Результати й пропозиції: що виміряно, простими словами, потім пакети змін і поради щодо вхідних каналів (дивіться нижче).
  13. Застосувати зміни: записує вибрані пакети після свіжого читання пульта й введеного слова (дивіться нижче).
  14. Контрольний замір: ще раз вимірює кілька місць і каже, чи стало краще (дивіться нижче).
  15. Що далі: що робити після цієї сесії, зокрема зберегти сцену на пульті під новою назвою.

План точок вимірювання

Перед раундами вимірювань майстер складає план місць, де сидять люди:

  • Щонайменше 8 місць у середній частині зали, не в центральному проході, на нерівних відстанях одне від одного.
  • Кожне місце описане словами з відстанями, наприклад «передні ряди, ліворуч, приблизно 6 м від сцени, 3,5 м лівіше від центрального проходу». Ліворуч і праворуч — якщо стояти обличчям до сцени.
  • Проста схема зали показує сцену вгорі й нумерує лише місця поточного раунду.
  • Мікрофон ставлять на висоті вух людини, що сидить (1,2 м), капсулем до сцени. Після Enter у вас є 3 секунди, щоб відійти щонайменше на 2 м.
  • Якщо розмір зали не вказано, план розрахований на типову залу 12 × 18 м, і мікрофони ставлять приблизно.
  • План зберігається для цього приміщення, щоб пізніший контрольний замір міг використати ті самі місця.

Пакети змін і поради щодо каналів

Після результатів майстер пропонує зміни пакетами. Кожен пакет має окремий екран:

  • таблиця змін: де, значення зараз і запропоноване значення;
  • чому зміна допомагає, очікуваний ефект і ризик;
  • питання «Додати … до плану змін?» з варіантами «Додати до плану» чи «Не додавати».

Якщо пакет не додати, наступні пакети розраховуються заново без нього, тож нічого в плані не залежить від зміни, яку ви не вибрали. Вибір зберігається в теці сесії у файлі proposal.json.

Сьогодні майстер пропонує лише еквалайзер системи: м'які корекції того, що зала робить зі звуком на більшості місць. Вузькі провали на окремих місцях він не чіпає, бо еквалайзер їх не виправить. Кросовер, вирівнювання й рівень сабвуфера потребують окремого заміру сабвуфера й основних колонок. Майстер поки цього не робить (потрібні тимчасові mute, вони будуть у M5), тому їх не пропонує й пояснює чому: кросовер, виставлений наосліп, може залишити провал у басах.

Далі йдуть поради щодо вхідних каналів. Програма сама їх ніколи не змінює; ви вирішуєте на слух, по одному налаштуванню, на репетиції:

  • голоси без зрізу низів (фільтра високих частот, HPF) або з дуже високим зрізом;
  • вузькі вирізи, що, ймовірно, захищають від заводки: зробити їх щонайбільше вдвічі мілкішими, на репетиції, з увімкненими моніторами;
  • вирізи, спільні для багатьох каналів;
  • дуже глибокі вирізи: перевірити, чи вони ще потрібні, по 3 дБ;
  • сильні підйоми, які можуть спричинити заводку;
  • фантомне живлення (+48V) на тому, що схоже на динамічний мікрофон: вимикати його лише тоді, коли канал вимкнено (mute).

На цьому кроці в пульт нічого не записується. Запис буде на наступному кроці, «Застосувати зміни».

Застосування змін

Після пропозицій крок Застосувати зміни записує вибрані пакети:

  • Спершу він ще раз читає пульт. Якщо хтось змінив налаштування після заміру, він відхиляє план і просить виміряти заново, щоб план завжди відповідав тому, що зараз на пульті.
  • Він показує кожне налаштування, яке запише, зі значенням зараз і новим значенням, у тому порядку, в якому записуватиме.
  • Щоб записати, введіть слово застосувати (в англійському інтерфейсі apply, у російському применить) і натисніть Enter. Будь-що інше скасовує, і нічого не записується.
  • Старі значення зберігаються у файл скасування до першого запису.
  • Порядок записів вибрано так, щоб звук ніколи не ставав гучнішим посередині.
  • Кожне значення перечитується з пульта. Якщо якесь не підтвердилося, майстер зупиняється на ньому й пропонує повернути вже записане.
  • Затримку виходу й полярність програма не записує. Вона показує їх як значення, які ви виставляєте на пульті вручну.

Контрольний замір

Потім крок Контрольний замір ще раз вимірює щонайменше чотири місця, серед них місце, що звучало найгірше, і місце посередині зали. Поставте мікрофони точно туди, де вони стояли раніше. За чіткими правилами майстер каже одне з трьох: краще, помітної різниці немає або гірше, з невеликою картинкою «до і після». Якщо стало гірше, він радить повернути старі значення й одразу пропонує це зробити.

Останній екран нагадує зберегти сцену на пульті під новою назвою (наприклад, із сьогоднішньою датою), щоб нові налаштування збереглися після перезапуску. Він також показує команду, якою пізніше можна повернути старі значення.

Застосування й скасування з термінала

Експертний командний рядок робить те саме: ctune apply-packages записує вибрані пакети зі збереженого proposal.json, а ctune undo повертає старі значення. Використовуйте їх лише з емулятором і CTUNE_DEV_SAFE=1. Їм потрібен proposal.json із сесії майстра (у теці сесії, <home>/venues/<зала>/sessions/<час>-<мета>/). Демонстрація на емуляторі поки не доходить до пропозицій (дивіться нижче), тож зараз це здебільшого для розробників.

Спершу подивіться, нічого не записуючи. --dry-run показує налаштування, які було б записано, по порядку, і зупиняється:

CTUNE_DEV_SAFE=1 uv run ctune --emulator apply-packages SESSION/proposal.json --dry-run

--emulator запускає новий емулятор лише на одну команду. Щоб записати, а потім скасувати, тримайте один емулятор запущеним в окремому терміналі (він друкує свій порт) і спрямуйте на нього обидві команди, замінивши PORT, SESSION і UNDO_FILE:

CTUNE_DEV_SAFE=1 uv run ctune emulator --model X32P
CTUNE_DEV_SAFE=1 uv run ctune --console 127.0.0.1:PORT --audio fake --home /tmp/ctune-demo apply-packages SESSION/proposal.json
CTUNE_DEV_SAFE=1 uv run ctune --console 127.0.0.1:PORT --audio fake --home /tmp/ctune-demo undo UNDO_FILE

apply-packages зберігає файл скасування до першого запису й друкує його назву (він лежить у теці undo всередині --home). undo повертає лише ті значення, які відтоді не змінювали вручну, і перелічує ті, що залишає як є. Обидві команди також приймають --dry-run. Їхні тексти поки російською, тож вони просять ввести російські слова применить (застосувати) і вернуть (повернути).

Безпека перед будь-яким звуком

  • Майстер ніколи сам нічого не вимикає й не вмикає. На справжньому пульті канали вимірювальних мікрофонів ви вимикаєте (mute) вручну, а він підказує, які саме.
  • Перед першим звуком він ще раз читає пульт. Доки канал, що слухає вимірювальний мікрофон, не вимкнено й він може потрапити в колонки, майстер відмовляється відтворювати будь-який звук, бо це може дати заводку.
  • Ця перевірка бачить канали. Мікрофон, скерований прямо на вихід в обхід каналу, поки не перевіряється, тож перевірте маршрутизацію самі.
  • Перед кожним звуком спершу є екран-попередження («Відтворити тестовий звук» або «Ще ні»), а раунди вимірювань відраховують 3 секунди.

Що ви побачите в демонстрації

В емуляторі канал вимірювального мікрофона (канал 12) спочатку не вимкнено, а вимкнути його вручну в емуляторі поки не можна. Тому демонстрація зупиняється на кроці Шлях відтворення з повідомленням, що канал 12 досі подає вимірювальний мікрофон у колонки і його треба вимкнути на пульті. Повторне Enter лише повторює перевірку. Це спрацьовує правило безпеки, а не помилка. Пройдіть перші кроки, а потім збережіть і вийдіть (Ctrl+Q або Q у рядковому інтерфейсі).

Тому до плану точок, пакетів змін, застосування й контрольного заміру, описаних вище, у демонстрації на емуляторі поки не дійти. Їх перевіряють автоматичні тести: у них майстер проходить усі кроки, разом із застосуванням і контрольним заміром, на емуляторі й імітованому залі.

Чого він поки не робить

  • Пропонує лише еквалайзер системи. Кросовер, рівень і затримка сабвуфера потребують окремого заміру сабвуфера й основних колонок, а для нього потрібні тимчасові mute. І те, і інше ще попереду в M5; до того майстер ніколи не пропонує кросовер.
  • Ще немає попередження про великі зміни рівня сабвуфера й режиму без запитань (M5).
  • Перевірка колонок по одній теж потребує тимчасового mute, тож вона з'явиться в майстрі разом з M5. Зараз вона є лише як експертна команда.
  • Файлу звіту ще немає (M6).
  • На справжньому пульті майстер ще не запускали, і запис у справжній пульт не перевірено на обладнанні. Для цього потрібні перевірки обладнання й пілот (M7).

Для власників пультів: перевірка обладнання

Деяку поведінку пульта може підтвердити лише людина за справжнім пультом. Кожна перевірка — це один рядок чек-листа обладнання (англ.). Ваш звіт переводить функцію з режиму «лише порада» в режим «ChurchTune може це записувати» для цієї моделі й прошивки.

Перед початком

  • Лише в порожньому залі, ніколи під час служіння чи репетиції.
  • Тримайте систему на безпечному, низькому рівні.
  • Спершу збережіть сцену на пульті, щоб можна було все відновити.
  • Установіть версію для розробників на Mac (див. Встановлення вище) і підключіть його до мережі пульта.

Кроки

  1. Відкрийте чек-лист обладнання і виберіть рядок для свого пульта. Рядки 1 і 2 (ctune hwcheck delay і ctune hwcheck polarity) можна пройти вже сьогодні; інші залежать від функцій, які ще в розробці. Рядки 22–25 перевіряють новий запис з етапу M5 (застосування, скасування й контрольний замір); для них потрібна гілка m5-apply, і людина має пройти їх у порожньому залі, перш ніж на ці записи можна покладатися.
  2. Прочитайте рядок: що перевірити, яку команду виконати й який результат очікується.
  3. Виконайте команду, стежачи за екраном пульта. Порівняйте те, що відбувається, з очікуваним результатом.
  4. Поверніть старе значення, як описано в рядку (файлом скасування або завантаженням своєї сцени).
  5. Надішліть результат через форму перевірки обладнання: номер рядка, модель і прошивку пульта, коміт ChurchTune (git rev-parse --short HEAD) і що ви побачили. Форма англійською, але писати можна й українською.

Дампи пультів

Дампи (лише читання) інших моделей, прошивок і маршрутизацій допомагають драйверу пульта (M1) розпізнавати більше систем. Спершу приберіть назви й усе особисте; як це зробити, пояснює посібник для учасників.

Згодом: налаштування вашої системи Згодом

Так планується робота повного майстра в справжньому залі після завершення етапів M5 і M6. Читання пульта, вимірювання, аналіз, пропозиції, застосування й контрольний замір уже є в майстрі (дивіться вище), пропозиції поки лише для еквалайзера системи; звіт буде в M6.

Запис у справжній пульт ще не перевірено на обладнанні. Застосування, скасування й контрольний замір перевірені лише на емуляторі з імітованим залом. Дочекайтеся перевірок обладнання, перш ніж використовувати їх на системі своєї церкви.

  1. Прочитати пульт. ChurchTune знаходить пульт і показує, що знайшов, наприклад: «X32 Producer, основні колонки на Matrix 1/2, сабвуфер на Matrix 3. Правильно?». Питає лише те, чого не може прочитати.
  2. Виміряти. Визначає вхід мікрофона, перевіряє шлях сигналу коротким тихим тоном, підбирає рівень, а потім показує просту схему точок і веде вас: «поставте мікрофон сюди, натисніть Enter».
  3. Проаналізувати. Усереднює точки й оцінює зал, зокрема як довго він звучить і як сабвуфер стикується з основними колонками.
  4. Запропонувати. Простими словами показує проблеми й пропонує кілька змін, кожну з коротким «навіщо».
  5. Застосувати. Ви бачите кожну зміну й підтверджуєте її, ввівши слово; спершу зберігається файл скасування, а кожне значення перевіряється після запису.
  6. Перевірити й звітувати. Вимірює ще раз, показує «до» і «після», пропонує скасувати, якщо не стало краще, зберігає звіт і нагадує зберегти сцену на пульті.
